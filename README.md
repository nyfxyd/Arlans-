# Arlans-
Подбор университетов и маршрут поступления для абитуриентов Казахстана.
База — 356 вузов из 34 стран: 48 кураторских записей с полными данными (включая 18 вузов РК)
плюс 308 из внешней базы universities_database v2.0. Скоринг считается в браузере
(мгновенные слайдеры What-If), аргументацию и диагностику пишет Gemini через бэкенд на FastAPI.

Важное про данные: во внешнем источнике у многих вузов не заполнены IELTS, дедлайны и стоимость.
Приложение это не скрывает — такие вузы попадают в отдельную категорию «Нет данных», на карточке
стоит пометка о том, каких полей не хватает, а скоринг за отсутствующее поле не штрафует.

## Шаг 1. Ключ Gemini

Ключ выдаётся в [Google AI Studio](https://aistudio.google.com/apikey). С мая 2026 года Google
выпускает только Auth-ключи вида `AQ.Ab...` — это нормальный текущий формат, не OAuth-токен.
Старые Standard-ключи (`AIzaSy...`) Google отключил в сентябре 2026. Разница не только в виде
ключа: Auth-ключи нужно передавать в заголовке `x-goog-api-key`, а не в `?key=` в URL — в коде
(`ai_service.py`) это уже учтено.

```bash
cp .env.example .env
```

Откройте `.env` и впишите ключ:

```
GEMINI_API_KEY=AQ.Ab...ваш_ключ
GEMINI_MODEL=gemini-2.0-flash
```

`.env` в git не попадает (прописан в `.gitignore`). Ключ, который уже был отправлен в чат
или закоммичен, считается скомпрометированным — отзовите его и выпустите новый.

Без ключа приложение тоже работает: бэкенд отдаёт детерминированную аналитику
(`source: "fallback"`), а фронтенд — встроенный скоринг.

## Шаг 2. Бэкенд

```bash
./run_backend.sh
```

Или вручную:

```bash
python3 -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn backend.main:app --reload --port 8000
```

Проверка: http://127.0.0.1:8000/docs — интерактивная документация.

## Шаг 3. Фронтенд

```bash
./run_frontend.sh          # http://127.0.0.1:5500/unipulse.html
```

Файл `frontend/unipulse.html` самодостаточен: можно просто открыть его двойным кликом,
залить на любой статический хостинг или встроить в Next.js как страницу.
База вузов вшита внутрь, поэтому интерфейс работает и без бэкенда — в шапке загорится
«Офлайн-режим», недоступной будет только аргументация от ИИ.

Адрес бэкенда по умолчанию `http://127.0.0.1:8000`. Поменять можно прямо в интерфейсе:
кнопка «Изменить адрес бэкенда» в плашке ошибки; значение сохраняется в браузере.

## Шаг 4. Проверка Gemini

```bash
curl http://127.0.0.1:8000/health
# {"status":"ok","ai_configured":true,"model":"gemini-2.0-flash","universities":48}
```

Живой запрос:

```bash
curl -X POST http://127.0.0.1:8000/api/recommend \
  -H "Content-Type: application/json" \
  -d '{"track":"both","target_major":"Computer Science","ent_score":112,
       "ent_subjects":["Математика","Физика"],"gpa":4.6,"ielts":6.0,
       "budget_kzt_per_year":3000000,"career":"build",
       "shortlist":["aitu","kbtu","agh"]}'
```

В ответе поле `source`: `gemini` — ключ работает, `fallback` — ключ не задан или Gemini недоступен
(причина будет в логах uvicorn).

Логика без сети проверяется так:

```bash
python -m tests.smoke_test
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | статус, модель, число вузов |
| GET | `/api/universities?country=Польша&type=international` | база с фильтрами |
| POST | `/api/universities/reload` | перечитать JSON после парсера |
| POST | `/api/recommend` | профиль → фильтры → шорт-лист → разбор от Gemini |

Как устроен `/api/recommend`: клиент присылает профиль, свой локальный шорт-лист
(`shortlist`) и посчитанные проценты (`client_scores`). Бэкенд прогоняет жёсткие правила,
берёт до восьми вузов и просит Gemini объяснить каждый, назвать риск и действия.
Модель не решает, кто проходит по деньгам и баллам — это делает детерминированный код.

Ошибки: 422 — профиль невалиден или ни один вуз не прошёл фильтры; 500 — проблема Gemini
с человекочитаемым текстом (таймаут, лимит, неверный ключ). При `ALLOW_MOCK_FALLBACK=true`
сбой Gemini не роняет ответ, а подменяется офлайн-аналитикой.

## Данные

Кураторские записи правятся в `backend/data/build_universities.py` (одна строка `L(...)` — один вуз).
Внешняя база подмешивается скриптом `backend/data/merge_external_db.py`: он приводит её к схеме
приложения, конвертирует валюты в тенге по курсам из словаря `FX`, помечает оценочные расходы
флагом `cost_estimated` и сливает дубли (кураторская запись побеждает, из внешней добираются
сайт, конкурс, взнос и визовые данные). После правок:

```bash
python backend/data/build_universities.py
curl -X POST http://127.0.0.1:8000/api/universities/reload
```

Чтобы обновлённая база попала во фронтенд, пересоберите вшитый массив:

```bash
python - <<'EOF'
import json, pathlib, re
db = json.load(open('backend/data/universities.json', encoding='utf-8'))
p = pathlib.Path('frontend/unipulse.html'); html = p.read_text(encoding='utf-8')
p.write_text(re.sub(r'const DB = .*?;\n', 'const DB = ' + json.dumps(db, ensure_ascii=False) + ';\n', html, count=1, flags=re.S), encoding='utf-8')
EOF
```

Поля вуза: пороги (`ent_passing_score`, `ielts_min`, `sat_recommended`, `gpa_min`),
деньги (`tuition_kzt`, `rent_kzt`, `transport_kzt`, `living_kzt`), `scholarship`, `dorm`,
`vibe` (теги среды), `teaching` (практика / наука / индустрия),
`weights` (насколько сильно для этого вуза значат предметы, баллы, бюджет и среда),
`deadlines` (подача, стипендия, документы — из них строится Roadmap).

## Гранты и стипендии

Финансирование разбирается функцией `parseGrant()` по тексту поля `scholarship` и стоимости
обучения: `full` — покрытие полное или обучение бесплатное, `partial` — скидка либо частичная
стипендия, `unknown` — в источнике данных нет. Из 356 вузов сейчас 61 с полным покрытием,
25 с частичным.

`grantChance(uni, profile)` оценивает шанс: для казахстанских вузов по запасу к проходному
баллу (от 20 баллов — высокий, от 8 — средний, ниже — низкий), для зарубежных — по языку
и SAT относительно требований программы. Оценка честно помечена как ориентир: конкурс на грант
пересчитывается каждый год.

В плане поступления грант — отдельная кампания из шести шагов: выбор специальностей,
сбор документов, ЕНТ, подача заявления, результаты конкурса и зачисление. Даты ориентировочные,
в тексте задач стоит отсылка к приказу МНВО.

## Что где настраивается

| Задача | Файл |
|---|---|
| Модель, таймаут, CORS, курс доллара | `backend/config.py` и `.env` |
| Формулировки промпта | `ai_service.py`, константа `SYSTEM_PROMPT` |
| Правила отсева | `filtering.py`, функции `_check_local` / `_check_international` |
| Веса скоринга | функция `score()` в `frontend/unipulse.html` + поле `weights` у вуза |
| Границы Safety / Target / Reach | `categoryOf()` там же |
| Пороги шанса на грант | `grantChance()` в `frontend/unipulse.html` |
| Даты грантовой кампании | функция `tasks()`, блок `if(hasLocal)` |
| Тексты подсказок на экранах | объект `HINTS` в начале скрипта |

## Что хранится в браузере

`localStorage`, ключ `unipulse.v1`: профиль, отмеченные задачи, вузы в сравнении,
положения слайдеров симулятора, адрес бэкенда и последний открытый экран.
Кнопка «Сбросить все данные» на экране «Фокус» очищает всё. Запись обёрнута в try/catch,
поэтому в приватном режиме приложение работает, просто без сохранения.

## Жёсткие правила анкеты

Трек поступления и список стран — не подсказка, а фильтр. Функция `pool()`
в `frontend/unipulse.html` отсекает базу один раз, и диагностика с подбором
считают по одному и тому же набору: при «только за рубеж» вузы Казахстана
не появляются ни в списках, ни в счётчиках диагностики.

Выбранная специальность работает так же: `majorFit()` сверяет направление
со списком программ вуза по словарю `MAJOR_KEYWORDS` и возвращает `yes`,
`generic` (вуз публикует общий набор — направление уточняется на сайте)
или `no`. Вузы с `no` скрыты, пока пользователь не нажмёт «Показать все
направления»; счётчик скрытых виден над списком.

## Шкала совпадения

Слагаемые складываются как раньше, но итог проходит логистическое сжатие
(`4 + 94/(1+e^-(raw-50)/18)`). Раньше линейная сумма упиралась в пол 6%
и склеивала сотни вузов на одном значении. Бюджет и конкурс считаются
непрерывно, а не ступенями; при равном проценте вперёд выходит тот вуз,
где полная стоимость года ниже.

Для вузов без опубликованных требований `ieltsHint()` достаёт ориентир
по языку из текстовой справки (`ielts_note`) — категория «нет данных»
сократилась с 132 вузов до 30.

## Откуда берутся деньги в расчётах

Стоимость жизни считается не по вузу, а по стране: за основу взяты официальные
требования к финансовым гарантиям для студенческой визы (Sperrkonto в Германии,
GIC в Канаде, £1 171/мес вне Лондона в Великобритании, €10 180 в Италии)
и публикуемые вузами cost of living. Для дорогих городов — Нью-Йорка, Лондона,
Цюриха, Мюнхена, Бостона, Токио — применяется надбавка 1.25–1.4. Сумма разбивается
на жильё (50%), транспорт (10%) и быт с питанием (40%), основание расчёта видно
в карточке вуза под структурой расходов.

Плата за обучение берётся из источника. Отдельно поправлена Бавария: TUM с зимнего
семестра 2024/25 берёт с не-ЕС студентов €2 000–3 000 за семестр, поэтому
«190 000 ₸ за год» там больше не показывается.

## Гранты и стипендии

`grantChance()` даёт уровень шанса и перечисляет, что именно проверено
(балл против порога для Казахстана, IELTS и SAT против ориентиров вуза для
зарубежных). `grantHowTo()` собирает пошаговый порядок действий: куда подаётся
заявление, по какой группе идёт конкурс, какие документы нужны и к какому сроку.
Для вузов США шаги различаются по типу финансирования — need-based, need-aware
и merit-based требуют разного.
