# UniPulse AI — техническая спецификация

Дата: 19 сентября 2026. Версия приложения 1.0.0.

---

## 1. Модель ИИ

**Модель:** Google **Gemini 2.0 Flash** — строка модели `gemini-2.0-flash`. Задаётся переменной окружения `GEMINI_MODEL`, поэтому подменяется на `gemini-1.5-flash` без правок кода. Вся логика в `backend/ai_service.py`.

**Роль модели.** ИИ не считает шансы и не отбирает вузы. Скоринг, жёсткие правила по деньгам и баллам, категории Safety / Target / Reach — детерминированный код в браузере. Gemini получает уже готовый шорт-лист и только аргументирует: почему вуз подходит этому абитуриенту, какой главный риск, какие 2–3 действия предпринять. Это сделано намеренно: цифры не должна выдумывать языковая модель.

**Параметры вызова** (`generationConfig`):

| Параметр | Значение | Зачем |
|---|---|---|
| `temperature` | 0.4 | сдержанные, предсказуемые формулировки |
| `responseMimeType` | `application/json` | модель обязана вернуть JSON, а не markdown |
| `maxOutputTokens` | 4096 | хватает на разбор шорт-листа из 8 вузов |
| `systemInstruction` | `SYSTEM_PROMPT` | роль, правила, схема ответа |
| таймаут | 45 с | `AI_TIMEOUT_SECONDS` |

**Промпт.** Системная инструкция фиксирует роль приёмного консультанта и жёсткие правила:

- отвечать только валидным JSON-объектом, без markdown и текста вокруг;
- `university_id` брать строго из переданного списка — вузы не выдумывать;
- цифры в аргументации — только из входных данных;
- язык русский, тон спокойный и конкретный;
- каждое поле `why` и `risks` — 1–2 предложения.

Профиль абитуриента и шорт-лист подставляются двумя JSON-блоками через `build_prompt()`. Профиль передаётся с русскими ключами (`балл_ЕНТ`, `бюджет_тенге_в_год`, `карьерный_трек`), вуз — с полями `порог_ЕНТ`, `IELTS_min`, `SAT`, `обучение_тенге`, `полная_стоимость_тенге`, `дедлайн_подачи`, `полнота_данных` и локальным скорингом клиента.

**Формат ответа** — строгий JSON:

```json
{
  "summary": "2-3 предложения: общий вывод по абитуриенту",
  "strengths": [{"title": "коротко", "detail": "объяснение с цифрами"}],
  "limits":    [{"title": "коротко", "detail": "объяснение с цифрами"}],
  "insights": [
    {"university_id": "id", "why": "почему подходит",
     "risks": "главный риск", "actions": ["действие", "действие"]}
  ],
  "focus_advice": "одно предложение: что сделать на этой неделе"
}
```

**Разбор и устойчивость.** Ответ проходит через `parse_ai_json()`: снимаются возможные обёртки ` ```json `, вырезается объект между первой `{` и последней `}`, затем валидация Pydantic-схемой `AIResult`. При невалидной структуре — одна повторная попытка, потом `AIServiceError` с человеческим текстом.

**Три уровня деградации:**

1. `source: "gemini"` — живой ответ модели.
2. `source: "fallback"` — ключа нет, а `ALLOW_MOCK_FALLBACK=true`: `build_fallback()` собирает детерминированную аналитику из тех же слагаемых скоринга.
3. Бэкенд вовсе недоступен — фронтенд считает разбор прямо в браузере (`localInsights()`, `localFocus()`) и помечает его бейджем «разбор», а не «ИИ».

## 2. API бэкенда

FastAPI, четыре эндпоинта. Точка входа `backend/main.py`, запуск `uvicorn backend.main:app --reload --port 8000`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | статус, наличие ключа, модель, размер базы |
| GET | `/api/universities` | список вузов, фильтры `?country=` и `?type=` |
| POST | `/api/universities/reload` | перечитать JSON с диска без рестарта |
| POST | `/api/recommend` | основной сценарий: профиль → рекомендации |

Документация Swagger доступна на `/docs`, OpenAPI-схема на `/openapi.json`.

### GET /health

```json
{"status": "ok", "ai_configured": true, "model": "gemini-2.0-flash",
 "fallback_enabled": true, "universities": 356}
```

### POST /api/recommend

Конвейер: `load_universities()` → `apply_hard_rules()` → `pick_for_ai()` (максимум 8 вузов) → `analyze()`.

Запрос — объект `StudentProfile`:

```json
{
  "name": "Айгерим", "track": "both", "target_major": "Медицина",
  "ent_score": 112, "ent_subjects": ["Химия", "Биология"],
  "gpa": 4.8, "ielts": 8.0, "sat": 1550,
  "preferred_countries": ["Германия"], "needs_scholarship": true,
  "budget_kzt_per_year": 3000000,
  "career": "care", "horizon": "...", "work_format": "...",
  "shortlist": ["tum", "kaznmu"], "client_scores": {"tum": 74}
}
```

Ответ — `RecommendResponse`:

```json
{
  "source": "gemini", "model": "gemini-2.0-flash",
  "total_universities": 356, "passed_hard_filters": 41,
  "filtered_out": [{"id": "...", "name": "...", "reason": "..."}],
  "analyzed": ["tum", "kaznmu"],
  "result": { "summary": "...", "strengths": [], "limits": [], "insights": [], "focus_advice": "..." }
}
```

**Коды ошибок:** `422` — ни один вуз не прошёл фильтры (с подсказкой, что менять); `500` — сбой ИИ-сервиса или битый файл данных. Ошибки Gemini переводятся в понятный текст: `429` → превышен лимит, `401/403` → неверный ключ, таймаут → «сервис не ответил вовремя».

**CORS.** Разрешённые источники в `CORS_ORIGINS`, по умолчанию `localhost:3000`, `127.0.0.1:5500`, `claude.ai` плюс regex `https://*.claude.ai`. Важная деталь: страница по `https` не может обращаться к `http://127.0.0.1:8000` — локально фронтенд нужно открывать через `python -m http.server 5500`.

## 3. Библиотеки и зависимости

### Бэкенд (`requirements.txt`) — пять пакетов

| Пакет | Версия | Роль |
|---|---|---|
| `fastapi` | 0.115.6 | веб-фреймворк, маршруты, валидация, Swagger |
| `uvicorn[standard]` | 0.34.0 | ASGI-сервер |
| `pydantic` | 2.10.4 | схемы данных и строгая валидация ответа ИИ |
| `python-dotenv` | 1.0.1 | чтение `.env` |
| `httpx` | 0.28.1 | HTTP-клиент к Gemini |

Официальный SDK Google намеренно не используется: запрос к Gemini — один POST, а лишняя зависимость тянет транзитивные пакеты и усложняет замену модели. Python 3.11+.

### Фронтенд — без сборки

Один файл `frontend/unipulse.html`, около 1 МБ вместе с вшитой базой. Ни webpack, ни npm, ни node_modules.

| Библиотека | Как подключена | Роль |
|---|---|---|
| Tailwind CSS | CDN | вся вёрстка утилитарными классами |
| Lucide Icons | CDN | иконки |
| Google Fonts | CDN | типографика |

Состояние — обычный объект `state` плюс `localStorage` (ключ `unipulse.v2_clean`). Роутинг — по хешу (`#/matches`, `#/university/kaist`). Ванильный JavaScript, никакого React.

## 4. Внешние сервисы

**Google Gemini API** — единственный внешний сервис.

- Эндпоинт: `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
- Аутентификация: заголовок **`x-goog-api-key`**, а не query-параметр `?key=`.
- Формат ключа: с мая 2026 Google выдаёт Auth-ключи с префиксом **`AQ.`**. Старый формат `AIzaSy...` Google отключил в сентябре 2026. Заголовок понимает оба варианта, поэтому он и выбран.
- Где взять: `https://aistudio.google.com/apikey`
- Ключ живёт только в `.env`, в репозиторий не коммитится. Файл `.env.example` — шаблон без секрета.

**Курс валют.** Внешнего сервиса нет: курс зафиксирован константой `USD_KZT_RATE=540` на 17 сентября 2026 и продублирован во фронтенде в `APP_CONFIG.FX`. Это осознанное ограничение — автоматического обновления пока нет.

**Больше никаких внешних вызовов.** Нет аналитики, нет трекеров, нет базы данных. Фронтенд работает полностью офлайн, если не нажимать «Разбор от ИИ».

## 5. Данные

**Объём:** 356 вузов, 34 страны, 29 полей в записи.

| Источник | Записей | Полнота |
|---|---|---|
| `curated` — собрана вручную | 48 | `complete` |
| `db2` — внешняя база v2.0 | 308 | `partial` |

При слиянии 24 дубля объединены, приоритет у кураторской записи. Скрипт слияния — `backend/data/merge_external_db.py`, генератор кураторской части — `build_universities.py`.

**Структура записи** (`University` в `models.py`): идентификаторы и география; требования (`ent_passing_score`, `ielts_min`, `sat_recommended`, `gpa_min`); деньги (`tuition_kzt`, `rent_kzt`, `transport_kzt`, `living_kzt`, `total_cost_kzt`); дедлайны четырьмя датами; качество преподавания тремя осями (практика, наука, индустрия); текстовые справки вуза (`ielts_note`, `gpa_note`, `sat_note`, `visa`, `post_study`); служебные флаги (`tuition_known`, `cost_estimated`, `source`, `data_status`).

**Принцип: не выдумывать.** Отсутствующие данные хранятся как `null`, а не как ноль. Вузы без измеримых требований попадают в отдельную категорию и помечаются на карточке. Там, где числа нет, но есть текстовая справка вуза, показывается справка, а не прочерк.

**Откуда деньги.** Стоимость жизни считается по стране, опираясь на официальные требования к финансовым гарантиям для студенческой визы: Sperrkonto в Германии (€11 904), GIC в Канаде (CAD 23 448), £1 171/мес вне Лондона, €10 180 в Италии. Для дорогих городов — Нью-Йорк, Лондон, Цюрих, Мюнхен, Бостон, Токио — надбавка 1.25–1.4. Сумма разбивается на жильё 50%, транспорт 10%, быт и питание 40%. Основание расчёта хранится в поле `living_basis` и показывается в карточке.

**Две копии базы.** `backend/data/universities.json` и вшитая копия внутри HTML. Синхронизируются скриптом; единого источника истины пока нет — это известный долг.

## 6. Методы проверки

**Валидация данных.** Pydantic v2 проверяет каждую запись при загрузке: типы, диапазоны (`ent_score` 0–140, `ielts` 0–9, `sat` 0–1600, `gpa` 0–5), обязательность полей. Битая запись роняет загрузку с внятной ошибкой, а не расползается по приложению молча.

**Валидация ответа ИИ.** Схема `AIResult` требует непустые `strengths` и `limits`, у каждого `Insight` — обязательные `university_id`, `why`, `risks`. Модель не может вернуть полупустой объект и выдать его за разбор.

**Жёсткие правила отбора** (`filtering.py`) — детерминированный код, не ИИ. Отдельные ветки `_check_local()` и `_check_international()`: деньги, баллы, профильные предметы, специальность, география. Каждый отсеянный вуз возвращается с причиной в `filtered_out`, то есть отказ всегда объясним.

**Smoke-тест** (`tests/smoke_test.py`, запуск `python -m tests.smoke_test`) — без сети:

- загрузка базы и применение фильтров на реальном профиле;
- формирование шорт-листа;
- сборка fallback-аналитики и проверка непустых полей;
- разбор ответа, обёрнутого в ` ```json ` — проверка, что обёртка снимается;
- перехват битого JSON с ожидаемым `AIServiceError`.

**Аудит фронтенда через Node.** JavaScript извлекается из HTML регуляркой, исполняется через `new Function(src)()` с заглушками `document`, `window`, `localStorage`, `location`, `lucide`, `fetch`. Так проверяются все восемь экранов на рендер без исключений, работа скоринга на контрольных профилях и корректность новых блоков — шаги получения гранта, локальный разбор, структура расходов. Этим же способом ловились реальные баги: `null`-дата дедлайна роняла два экрана через `localeCompare`, а скоринг схлопывал 230 вузов на нижнюю границу.

**Контрольные замеры.** После каждой правки прогоняется эталонный профиль (химия + биология, медицина, ЕНТ 112, IELTS 8, SAT 1550, GPA 4.8, бюджет 3 млн ₸) и сверяются итоговые цифры: Harvard — обучение 33,6 млн, быт 12,15 млн, итого 45,75 млн ₸; TUM — 2,92 млн обучение, 11,61 млн итого.

## Известные ограничения

- Курс 458 ₸/$ зафиксирован вручную, не обновляется.
- Две копии базы синхронизируются скриптом, а не автоматически.
- 30 вузов по-прежнему без измеримых требований.
- Фронтенд не покрыт автотестами — проверка полуручная через Node.
- Доступность доведена частично: не везде расставлены `tabpanel` и навигация стрелками.
